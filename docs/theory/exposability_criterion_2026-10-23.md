**日期**：2026-10-23

## 0 为什么需要这条判据

前九轮的共同困难是：说"这个门对不可见"时，无法区分三种原因——

1. **窗口太窄**（horizon < 需要的步数）；
2. **规则库缺规则**（内容改写不在库里）；
3. **交换关系没写全**（引擎推不出应有的交换）。

E55 已经排除第 3 种（qiskit L3 与 tket FPO 都能在 k=1 与 k=6 上解出"对角门穿控制位"）。
剩下 1 与 2 混在一起，无法在**不跑搜索**的前提下判定。

本判据把第 1 种单独抽出来，给出**精确、多项式时间、无需搜索**的判定：
给定 listing 与交换关系，"这一对门能否被交换律带到相邻"是**可判定**的，且所需步数就是两者的距离。

---

## 1 设定

固定一次 listing $L=(g_1,\dots,g_m)$，固定一个对称、反身的**独立性关系** $\bot$（"可交换"）：
$g_i \bot g_k$ 表示相邻交换 $g_ig_k \leftrightarrow g_kg_i$ 是合法动作。依赖关系 $\not\bot$ 为其补。

本项目的 $\bot$ 由 `_commutes` 给出，包含 9 条关系：`disjoint`、`same_single`、`same_axis_rotation`、
`z_family`、`cx_control_z`、`cx_target_x`、`cz_z`、`same_swap`、`same_cz`。

**配对谓词** $P(g_i,g_j)$：`pair_v1` 在相邻位置会触发的可约判定（`self_inverse`、`t_tdg`、`s_sdg`、
`rotation_zero`、`rotation_merge`）。

**定义 1（可曝光）**。给定 $i<j$ 且 $P(g_i,g_j)$，称该对**可曝光**，若存在一串相邻交换把 $g_j$ 左移到
$g_i$ 的紧邻位置，且每一步交换的两门都满足 $\bot$。定义**穿越距离** $D(i,j)=j-i-1$。

---

## 2 定理

> **定理 1（精确判据）**。设 $i<j$ 且 $P(g_i,g_j)$。该对可曝光 **当且仅当**
> $$\forall k,\ i<k<j:\quad g_k \bot g_i \ \wedge\ g_k \bot g_j .$$
> 此时穿越距离为 $D=j-i-1$，且 $D$ 是可曝光性所需交换步数的上界；若中间存在 $g_k=g_{k+1}$（同一门），
> 该次交换是状态不变的空操作，实际动作数可小于 $D$。

**证明**.

*（⇐ 方向：条件成立 ⇒ 可曝光）* 若所有中间门与 $g_i,g_j$ 都独立，则从 $k=j-1$ 递减到 $i+1$，依次交换 $(g_k,g_j)$。
每一步交换的两门都满足 $\bot$（因为 $g_k$ 与 $g_j$ 独立），共 $D$ 步后 $g_j$ 位于 $i+1$，与 $g_i$ 相邻。

*（⇒ 方向：可曝光 ⇒ 条件成立）* 设存在某个 $k\in(i,j)$ 使 $g_k \not\bot g_i$。在迹幺半群（trace monoid）中，
两个依赖字母的相对次序在所有等价字中保持不变：$g_k$ 无法越过 $g_i$，因此任何等价字里 $g_k$ 仍在
$g_i$ 之后；同理若 $g_k \not\bot g_j$，$g_k$ 仍在 $g_j$ 之前。于是 $g_k$ 恒处于两者之间，$g_i,g_j$ 永不成为相邻。$\square$

**推论 1（视野下界）**。若某次有界搜索的动作预算为 $h$，且 $D^\*(i,j) > h$（$D^\*$ 为实际最少动作数），
则该搜索**在任何状态预算下**都看不见这次约简。这正是 E47/E50 观测到的"视野门槛"，现在无需枚举即可算出。

**推论 2（闭包可判定）**。判定"该 listing 是否已无任何可曝光配对"需要 $O(m\cdot w)$ 次独立性查询，
其中 $w$ 为依赖连跑长度（本项目实测 $w\le 512$，QuantumWalk 类长 listing 上 $w\le 64$ 已足够）。

**推论 3（两个动作类）**。任一约简必属且仅属以下两类之一：
- **序类（order）**：存在可曝光配对，交换律单独可达；
- **内容类（content）**：无任何可曝光配对，必须由库中某条改写规则改变门的内容。

判据把"是否序类"变成 $O(m\cdot w)$ 的可判定问题，这是本项目此前一直缺少的**分类判据**。

## 3 算法：闭包（closure）

```
closure(L):
  repeat until fixpoint (≤12 passes):
    E ← { (i,j) : P(g_i,g_j) ∧ ∀k∈(i,j), g_k⊥g_i ∧ g_k⊥g_j }   # 定理 1
    select a non-overlapping subset of E, smallest D first
    for each selected pair, descending i:
        emit D exchange actions (bubble g_j to i+1)
        emit the pair_v1 action
```

每次发射的都是**引擎可重放的合法动作**，因此整条轨迹构成可验证证书（`replay_actions`）。
闭包是**不动点算子**：终止时不存在可曝光配对，即推论 2 的判定为真。

## 5 适用范围与已知限制

1. **判据依赖 $\bot$**。若交换关系本身不全（例如引擎没有 `cx_control_z`），判据会**错误地**报告不可曝光。
   本项目的自检（56,028 对 0 不一致）只保证"实现与引擎一致"，不保证"引擎与物理一致"。
2. **只判定单次约简的可达性**。串行约简后的新配对需要重算——闭包用不动点迭代覆盖，但**不保证全局最优**：
   贪心选择顺序会影响最终门数（E56 的 4 个"更差"单元即内容类，非顺序问题）。
3. **内容类不可由本判据判定**。内容类需要"哪条规则在哪个位置"的搜索，属另一问题。
4. **距离上限**。实现上对 $D$ 设自适应上限（>4000 门取 64，>1500 取 128，否则 512）。
   仅当真实 $D_{\min}$ 超过上限时结果才不精确；面板上未出现该情形。
5. **成本模型是门数**。两比特口径已在 E58（2026-10-24）补齐：128 源上闭包把总门数
   70,293 → 62,952（−10.44%），但两比特仅 24,538 → 24,408（**−0.53%**），
   两比特只占总收益的 1.77%，13/128 源有两比特增益。**本判据的一切收益陈述
   必须同时报两比特口径**；只报总门数会把单比特合并误当成容错成本收益。
