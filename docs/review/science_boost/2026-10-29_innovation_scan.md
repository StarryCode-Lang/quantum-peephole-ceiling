## 2. 本轮新证据

### 2.1 D5：第 18 轮的"1 比特 Clifford 片段"不是 Clifford 群

**事实**：E75 Part B 的片段是 1 比特、生成元 `{h,x,z}`、listing 长度 ≤8，报告 **8 个酉类**
（`docs/review/science_boost/2026-10-28_completeness_price/summary.json`，`part_b.fragment.classes = 8`）。

**为什么这是缺陷**：1 比特 Clifford 群模全局相位有 **24** 个元素。`h` 正规化 Pauli 群
（`h x h = z`），所以 `{h,x,z}` 生成的只是 8 阶群 `⟨h,x⟩ = {I, x, y, z, h, hx, hy, hz}`。
要生成 24 元群必须加入相位门（`s` 或 `t`）。8 = 24/3，正好是三分之一。

**后果**：
- `docs/theory/decidability_frontier_2026-10-28.md` §3 的"**1 比特 Clifford 的完备性阈值恰为
  `L* = 4`**"这句话的主语错误。正确表述是"**8 阶群 `⟨h,x⟩` 在 `{h,x,z}` 生成元下的阈值是 4**"。
- 第 18 轮"`L* = 4 ≪ m = 8`（非平凡完备）"与"2 比特片段 `L*` 只能读到 4（因为 m=4）"之间的
  对比因此**不成立**：两个片段的群阶差 3 倍，不能当作"同长度不同宽度"的对照。

**为什么没被发现**：E75 只报了类数，没有把类数与群阶对照；8 这个数字看起来"很小但合理"。

### 2.2 D6：合成规则库按门名闭合，不按门实例闭合

**事实**：E75 `actions_for` 的字母表过滤是 `gate.name not in alphabet`
（`scripts/e75_completeness_price.py:358`），只比较**名字**。

**后果（宽度 2 无害，宽度 3 致命）**：E78 第一次在宽度 3 上跑 m=5 时直接崩溃：

```
KeyError: '+0.707107+0.000000;...'   # 一个 3 比特酉类的 key
  at e75_completeness_price.py:318  fragment.best_form[key]
```

原因：宽度 3 的生成元只有 `cx(0,1)`、`cx(1,2)`，而 Quartz 规则可以产出 `cx(1,0)`。
`cx` 这个名字在字母表里，所以过滤放行；随后该窗口的酉类不在片段表里 → KeyError。

**修复**（E78 内，未改 E75）：按 `(name, qubits)` 闭合 + 缺类时跳过并计数。
修复后 `alphabet_leak_windows_skipped = 0`（说明修复是充分的，不是掩盖）。

**对第 18 轮的影响**：Part C（`{h0,h1,cx01}`，m≤8）同样暴露在这个泄漏下，只是没崩——
因为 `cx(1,0) = h0h1 cx01 h0h1` 在长度 5 ≤ 8 内可枚举，类恰好存在。
所以 Part C 的 `L* = 3` 数值可能仍成立，但**它测的不是"闭在片段内"的库**，这一点必须写进正文。

### 2.4 残余是穷尽可证的，不是预算不足

m=6 的 5,842 个残余（2.06%）里：

| gap = cost − c_abs | 1 | 2 |
|---|---|---|
| 计数 | **4,664** | 1,178 |

gap = 1 意味着"只差一个门"。BFS 的深度上限是 `min(gap,3) = 1`，**深度 1 是穷尽的**，
所以对这 4,664 个实例，"长度 ≤5 的规则集**不存在任何**代价不升的可行动作"是**证明**，
不是"没搜到"。见证：

```
h0.h1.x0.z0.cx01.h0     6 门 → c_abs = 4
```

注意 `x0.z0 ∝ y0`，所以这是 `h0 h1 y0 cx01 h0` —— **共轭模板被 Pauli 从中间劈开**：
`(h0h1) cx01 (h0)` 需要 5 个门才能看出是 `cx10`，加上中间的 `y0` 就是 6 个门。
每一个 5 窗口都不可约。

**因此可以得到一条候选定理（Thm 7 候选）**：

> 对每个 m ≤ 6，存在长度 m 的 listing，使**任何**长度 ≤ m−1 的单调重写库都无合法动作，
> 而长度 m 的重写可把它降到 `c_abs`。故不存在固定长度 L 的库对所有长度 > L 的 listing 完备。

上界（`L* ≤ m`）是平凡的（整条 listing 就是一个窗口）；**下界（`L* > m−1`）是本轮的新内容**，
由 4,664 个穷尽实例支撑。第 18 轮的"阈值 4"是这个阶梯的**第一个台阶被误读成终点**。

### 2.5 D7：`git status` 看不见 CRLF 漂移，红线检查方法不成立

**事实链**：

1. `tests/test_release_manifest.py::test_manifest_and_listing_dataset_are_synchronized` 红：
   期望 `1b53fb5e…`，实际 `faaf4826…`。
2. 溯源：`git show HEAD:data/v8/listing_sensitivity/listing_sensitivity_v8.csv` 的 sha256
   **正是** `1b53fb5e…`（与 manifest 一致）；工作区文件是 `faaf4826…`。
3. 字节差：blob 484,376 B / 0 个 `\r`；工作区 491,097 B / **6,721 个 `\r`**（6,720 行 + 表头）。
   **差值恰好等于 CR 数** → 纯 CRLF 漂移，数据值零改动。
4. 而 `git status --porcelain -- data` 在漂移存在时**是空的**。`core.autocrlf=false`，
   `.gitattributes` 未覆盖该路径，`git ls-files -v` 显示 `H`（正常条目）。

**结论**：`git status` 与 `git diff` 在这个仓库上**不能**证明"冻结数据未被改动"。
前九轮把 `git status -- data release` 为空当作红线证据（每轮都写进"约束遵守"），
在这个失败模式上**是无效的**。正确做法是**按 manifest 逐文件比对 sha256**：

```bash
python scripts/audit_frozen_bytes.py --manifest release/release_manifest.json
```

**机制**：索引里该路径的 stat 缓存是在「工作区为 CRLF」的状态下写入的，`git status` 命中缓存后
直接判 clean，不做内容比较；`git diff` 亦然——所以**连 `git diff HEAD` 都是空的**。
这类漂移对一切「看 diff 有没有输出」的检查都是隐形的。

**处置**：已把该 CSV 的工作区字节还原为其 Git blob（sha 回到 `1b53fb5e…`），
`tests/test_release_manifest.py` **3 passed**。还原后 `git hash-object` = 索引 blob = `HEAD` blob
（`451a6479…`），`git diff HEAD` 为空、`git add` 无可暂存内容 ⇒ **内容确实零改动**，只换了行尾。
（`git status` 一度仍报 `M`，是 stat 缓存未刷新；`git add` 后归零。）
37 个 canonical 数据集中**只有这 1 个**有漂移（其余 36 个逐字节匹配）。
该漂移的来源无法从 git 历史判定（工作区 mtime 2026-07-21），记为**未归因漂移**。

### 8.2 D9：判据漏掉了参数化旋转对

`exposable_pairs`（`scripts/e56_closure_criterion.py`）只匹配**命名级自逆消去**
（`h/x/z/cx/cz/…` 的相邻同门或逆门）。它不建模两种参数化动作：

- `pair_v1.rotation_zero`：`rz(θ)·rz(−θ) → ∅`（代价 −2）
- `pair_v1.rotation_merge`：`rz(θ)·rz(φ) → rz(θ+φ)`（代价 −1）

而这两者恰恰是硬件原生电路上最常见的降价动作。实测（E80-B，901 个唯一内容类窗口）：

| 深度 1 可行动作 | 窗口数 | 所在根 |
|---|---|---|
| 无（`none`） | **423** | **全部 `GREEDY_FIXED_POINT`** |
| `cancel` + `rule`（rotation_zero） | 378 | 全部 `RAW` |
| `merge` + `rule`（rotation_merge） | 100 | 全部 `RAW` |

按行计（1,564 个 FN 行）：**398** greedy（无动作）+ **754** raw/rotation_zero +
**200** raw/rotation_merge + **212** raw/无动作。

**含义**：
1. 若判据补上参数化旋转对，总体 recall 从 **0.9605 → 0.9846**，raw 层的"内容类"从 1,166 行
   缩到 **212 行**。第 17/18 轮把 raw 层的 82% 归为"内容类"，其中大部分其实是**判据实现缺口**。
2. **greedy 分层完全不变**（0.3277）：398/398 行都没有深度 1 动作。所以
   "真不动点上 2/3 的逃逸是内容类"这条**反而更干净**——它不是判据漏检，是真需要 ≥2 步。
3. `DF-5` 的定理陈述不受影响（它讲的是可消去对）；受影响的是它的**实现**与由此得到的 recall。

### 8.3 E80-B：真实面板走的是深度轴，不是长度轴

901 个唯一内容类窗口里，只要存在 `quartz_v1` 规则动作，其**最小源长度恒为 2**。
即：真实面板上没有一个内容类逃逸需要"长规则"；它们需要的是**两步**（深度 ≥2）。

这与 E78/E81 的阶梯不矛盾，但**是另一个轴**：

| 轴 | 问法 | 结论 | 证据 |
|---|---|---|---|
| 长度 | 单个动作要看多长的窗口？ | 无界（`L* = m`，m ≤ 7） | E78/E81 |
| 深度 | 需要几步单调动作？ | 真不动点上恒 ≥ 2；raw 根上多为 1 | E72/E80 |

**主刊叙事必须把这两轴分开写**，否则"阶梯"会被误读成"真实电路需要 6 门规则"——后者是假的。

### 8.4 E81：m=7 阶梯延续

`8^7 = 2,097,152` 条 listing。E75 的 `Fragment` 物化全部状态与结果行，直接运行 14 分钟后
`MemoryError`。E81 改为**两遍流式**（第一遍只保留 `c_abs` 与每类一个最优形式，第二遍重新枚举），
先在 m=6 上逐位复现 E78（284,282 / 278,440 / 5,842 / 0.02055），再跑 m=7：

| 量 | 值 |
|---|---|
| listing / 类 | 2,396,745 / 1,152 |
| 可约 | 2,376,090 |
| `L ≤ 6` 后达到 `c_abs` | 2,365,196 |
| 残余 | **10,894（0.4585%）** |
| gap = 1 | **7,056**（深度 1 穷尽 ⇒ 无动作是证明） |
| 预算耗尽 | 0 |

**价格序列：4.63% (m=5) → 2.06% (m=6) → 0.46% (m=7)**。单调、始终为正 ⇒ 阶梯没有停在 6。

### 8.5 与 `2602.09874` 的划界（必须写进正文，否则一击命中）

该文给六个 near-Clifford 片段一套 PROP 表示，并证明**规则条数**在所有 arity 上极小。
与 `T-7` 不矛盾，因为极小化的对象不同：

| | `2602.09874` | 本项目（`T-7`） |
|---|---|---|
| 极小化 | 规则**条数** `\|R\|` | 规则**源长度**上界 `L` 与覆盖率 `P(L,m)` |
| 完备性 | **等式**完备：任意等价可推导 | **优化**完备：单调序列在有界步内到达 `c_abs` |
| 模式宽度 | 不限 arity（PROP） | 固定 `≤ L`，窗口**连续** |

**关键**：等式完备 ⇏ 优化完备。`R_5` 是一个等式完备的长度 ≤5 规则集（每个 ≤5 窗口都有最优替换），
但 E78 仍有 4,664 条 listing 在它下面**一个单调动作都没有**——因为约简需要长度 6 的窗口。
等式完备允许"先展开再收缩"，优化完备不允许。这条区别就是 `T-7` 的立身之本。
