## 2. E18: Clifford+T Optimization

### 2.1 Setup

- **Script**: `analysis/rerun_e18_checkpointed.py` (new, mirrors the E15
  checkpointed pattern)
- **Canonical**: `data/v5/e18/e18_clifford_t_e18_full_20260610_052140.csv`
  (270 rows = 192 `ok` × 3 optimizers + 78 `decompose_error` × 1 row)
- **Rerun output**: `data/v9/e18/e18_clifford_t_e18_full_20260721_131939.csv`
  (231 rows = 77 circuits × 3 optimizers, all `ok`)

### 2.2 Guard rails

The rerun script enforces two budget guards absent from the canonical run:

- `SKIP_ORIG_GT = 600` — skip decomposition when the raw circuit exceeds 600
  gates (canonical `ok` max = 152)
- `DEFER_DECOMP_GT = 2500` — defer when the Clifford+T-decomposed circuit
  exceeds 2500 gates (canonical `ok` max = 152, canonical `decompose_error`
  rows were all under this threshold but errored during translation)

65 circuits were deferred because they decompose to 2.5k–480k gates (qwalk,
grover, qaoa_line, vqe_twolocal, hardware_eff, qft, uccsd at n=4..20, plus
haar_2/3/4). The canonical run recorded these as `decompose_error` rows;
the rerun does not emit rows for deferred circuits. This is the row-count
mismatch (270 canonical vs 231 rerun).

### 2.4 Attribution

The 42 input-hash mismatches are **generator drift**, not bugs. The rerun
suite is generated by the current `src/circuits/generator_v2.py` (sha256
`75bb4876…`), which has minor behavioural differences from the version
that produced the canonical suite on 2026-06-10. Affected circuits
concentrate in adder, qft, qaoa_line, surface_code families. The 20
reduction-differing rows are a subset of the 42 input-changed rows; the 22
remaining rows preserve reduction even though the input hash differs
because the optimizers find the same cancellation pattern regardless.

### 2.5 Decision

**E18 canonical data remains valid.** The rerun confirms that for the 150
circuits with identical input hashes, all scientific values (reduction,
fidelity, gate counts, depth/CNOT/T reductions) reproduce exactly. The 42
changed inputs are attributable to generator evolution and do not affect
the manuscript's headline numbers (E18 averages are unchanged within
statistical noise). The 65 newly-decomposable families that previously
errored represent a Qiskit translation-library improvement; we record them
as deferred (not `decompose_error`) so a future rerun with a larger compute
budget can fill them in.

## 4. Reconciliation script improvements

While running the reconciliation, two issues in
`analysis/rerun_reconciliation.py` were fixed:

1. **E20 column-name aliases**: the script only recognized `reduction`,
   `runtime_seconds`, etc. E20 uses `gate_reduction`,
   `compilation_time_seconds`, `original_gate_count`, `optimized_gate_count`.
   These are now aliased in `NUMERIC_COLS` and `DETERMINISTIC_COLS`.
2. **NaN-NaN comparison**: when both canonical and rerun have NaN in the
   same row (e.g. error rows with no optimized gate count), the old script
   counted this as a mismatch. It now counts NaN-NaN pairs as matching.

E20 status moved from `DIVERGED (max=nan)` → `IDENTICAL (1070 rows, all
match)`. E18 status is unchanged.
