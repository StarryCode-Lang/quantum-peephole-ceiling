> **Version**: 2.2.1 (merged; aligned with v5–v11 supporting data)
> **Last updated**: 2026-08-07
>
> This document provides a comprehensive description of all CSV columns
> generated by the Q-Research experiments (E1–E30, EHW hardware
> validation, the SOTA benchmark, and the listing-sensitivity check).
> It is the canonical reference for all column definitions across all
> experiments.

## Schema Families

The release uses six schema families. The `schema_version` column on each
row identifies which family it belongs to.

| Schema family | Experiments | Notes |
|---------------|-------------|-------|
| `legacy_v2_v3` | E1–E5, E10 | Greedy-bug-fixed + extended. Uses the legacy column names (`original_size`, `optimized_size`). |
| `results_v1` | E11–E13 | Real circuits, compiler baselines, structural ceilings. Introduces `circuit_id`, `circuit_type`, `*_sha256`, and `*_gate_count` aliases. |
| `results_v2` | E14–E18 | Extended suites, multi-compiler, window scaling, connectivity/topology, Clifford+T. Adds extended metrics and per-gate-class reduction columns. |
| `results_v6` | E19–E21, E25, E10p2b, E10-variance, E29-smoke, SOTA, ceiling-repair | WCL listing, multi-compiler full, ceiling-aware, industry benchmarks, review-driven supplements. |
| `results_v7` | E22–E24, E26, E29, E10p2b-full, E19-extended | Theory-validation experiments (AG canonical form, Theorem 7 hardness family, BV theory bounds) and full-mode re-runs superseding v6 smoke data. Minimal schema with core columns. |
| `results_v8` | EHW (hardware validation), Phase-2b full v2 | Backend-based validation: logical vs transpiled gate counts, exact unitary fidelity, noisy-sampling metrics (Hellinger/TVD); Phase-2b full-scale v2 (see `data/v8/phase2b_full/metadata.json`). |

> **Column-name aliasing**: `results_v1`/`results_v2` rows use
> `gate_count_total` / `baseline_gate_count` / `optimized_gate_count` for
> the same concepts that `legacy_v2_v3` rows call `original_size` /
> `optimized_size`. When joining across schemas, map:
> `original_size` ↔ `baseline_gate_count` (≡ `gate_count_total`),
> `optimized_size` ↔ `optimized_gate_count`.

## Common Columns

The following columns appear in **nearly all experiment output CSVs**.
Unless otherwise noted, a column is present in all six schema families.

| Column | Type | Description | Example |
|--------|------|-------------|---------|
| `schema_version` | `str` | Schema family for the row: `legacy_v2_v3`, `results_v1`, `results_v2`, `results_v6`, `results_v7`, `results_v8`. | `results_v2` |
| `experiment_id` | `str` | Unique identifier for the experiment run (e.g., `e10_p1vsp2_001`). | `e10_run_042` |
| `run_id` | `int`/`str` | Monotonic run index within the experiment (`int` in legacy; stable `str` identifier in results_v1/v2). | `42` |
| `circuit_id` | `str` | Stable circuit instance identifier (results_v1/v2 only). | `qft_n5_s01` |
| `circuit_family` | `str` | High-level circuit family (see taxonomy below). | `universal`, `qft`, `ghv` |
| `circuit_type` | `str` | Fine-grained circuit type (results_v1/v2 only). | `qft_full`, `bv_oracle` |
| `n_qubits` | `int` | Number of qubits in the circuit (system size). | `5`, `10`, `20` |
| `depth` | `int` | Original circuit depth (number of layers). | `20`, `50` |
| `seed` | `int` | Random seed used for circuit generation. | `42` |
| `trial` | `int` | Trial index (for repeated runs with same config). | `0`, `1`, `...` |
| `optimizer` | `str` | Optimizer name (see taxonomy below). | `greedy`, `sa`, `hybrid` |
| `original_size` | `int` | Gate count of the original (unoptimized) circuit. Legacy alias of `baseline_gate_count`. | `120` |
| `baseline_gate_count` | `int` | Gate count before optimizer/compiler under comparison (results_v1/v2). Equivalent to `original_size`. | `120` |
| `gate_count_total` | `int` | Input total gate count (results_v1/v2). Same value as `baseline_gate_count` / `original_size`. | `120` |
| `optimized_size` | `int` | Gate count after optimization. Legacy alias of `optimized_gate_count`. | `95` |
| `optimized_gate_count` | `int` | Gate count after optimizer/compiler (results_v1/v2). Equivalent to `optimized_size`. | `95` |
| `reduction` | `float` | Fractional gate reduction: `1 - optimized / baseline`. Range: `[0, 1]`. Proportion unless column ends in `_pct`. | `0.2083` |
| `reduction_pct` | `float` | Percent reduction: `100 * reduction` (results_v1/v2). | `20.83` |
| `fidelity` | `float` | Average gate fidelity between original and optimized circuits. Range: `[0, 1]`. | `0.9992` |
| `success` | `bool` | Versioned binary flag. Frozen v2_fixed--v8 optimizer rows generally used `reduction >= 0.20 AND fidelity >= 0.99`; future runs use `reduction >= 0.05 AND fidelity >= configured threshold`. Some legacy compiler rows used fidelity-only and must not be pooled as outcomes. | `True` |
| `runtime_seconds` | `float` | Wall-clock runtime of the optimization (seconds). | `0.342` |
| `timestamp_utc` | `str` (ISO 8601) | UTC timestamp when the row was generated. | `2026-05-15T08:23:17Z` |

## Experiment Datasets E19-E30, EHW, SOTA and Listing Sensitivity

Added in v2.2.0 (documentation-sync audit). Each subsection documents one
canonical dataset: dataset ID, canonical path, row count, schema tag, and
per-column definitions. Column meanings inferred from the column name and
the experiment script (rather than explicit code comments or metadata) are
marked **(inferred)**. Where a column reuses a common concept
(`n_qubits`, `depth`, `seed`, `trial`, `original_size`, `optimized_size`,
`reduction`, `fidelity`, `success`, `runtime_seconds`, ...), the
[Common Columns](#common-columns) semantics apply unless noted otherwise.

### SOTA: Compiler Benchmark Aggregate (v6)

- **Dataset ID**: `SOTA_BENCHMARK`
- **Canonical path**: `data/v6/sota_benchmark/aggregated/sota_comparison_aggregated.csv`
- **Rows**: 105
- **Schema tag**: none — this aggregate carries no `schema_version`,
  `experiment_id` or `timestamp_utc` columns; provenance lives in
  `data/v6/sota_benchmark/metadata.json` and the per-tool files under

the per-tool raw runs by `experiments/sota_benchmark.py`. **All
`*_reduction` summary columns are in percentage points** (computed from
the per-row `*_reduction_pct` columns of the raw runs), unlike the
fractional `reduction` convention used elsewhere.

   timestamp is recorded only in `data/v6/e21/metadata.json`
   (`2026-07-09T08:55:23`).
2. **E20 (and E21) use `gate_reduction`, not `reduction`.** The v6
   multi-compiler and ceiling-aware files name the gate-reduction column
   `gate_reduction` / `gate_reduction_pct`, and E20 also uses
   `original_gate_count` / `optimized_gate_count` instead of
   `baseline_gate_count` / `optimized_gate_count`. Values follow the same
   fractional/percent conventions as `reduction` / `reduction_pct`.
3. **Two column structures exist under the `results_v2` label.** The
   v5/e10 dataset (`data/v5/e10/e10_expanded_phase1_vs_phase2_20260613_131601.csv`)
   carries **no `schema_version` column at all** (header starts at
   `experiment,part,circuit_family,...`) and lacks the provenance block,
   while E14–E18 `results_v2` files carry the full extended-metrics +
   provenance schema. Joining code must not assume `schema_version`
   exists on every `results_v2`-family file.
4. **`schema_version` carries a dataset-schema semver in v6/v8 files.**
   In E19/E20/E21/E25/EHW the `schema_version` column holds a
   dataset-specific version tag (`1.0.0`, `1.1.0`, `2.1.0`), **not** a
   schema-family label (`results_v6`, `results_v8`). The family labels
   apply to the merged release files; the v7/v8/v10 minimal-schema files
   (E22–E24, E26, E27, E29, E30, listing sensitivity, SOTA aggregate)
   carry no `schema_version` column, and their schema tags are recorded
   only in the sibling `metadata.json`.
5. **Legacy experiment identifiers in row data.** E22 rows carry
   `experiment_id = E28_gate_shuffle_ablation` (the experiment was later
   renumbered E22), and E26 rows carry `experiment = E26_phase2b_full_v8`
   (renamed from `E10p2b-v2` / `E26_phase2b_full_v8` to `E26` on
   2026-08-06). Filter on the documented dataset ID, not on the legacy
   row value.
6. **`experiment` vs `experiment_id`.** E23 and E24 use a legacy
   `experiment` column containing the bare integer experiment number
   (`23`, `24`) rather than a string `experiment_id`; E26, E27 and the
   listing-sensitivity file also use `experiment` but with string values.
7. **E21 `fidelity_source` mislabel.** All rows are labelled
   `exact_average_gate_fidelity`, but for `n_qubits >= 8` the run used
   `target=None`, so `fidelity = 1.0` is a placeholder default, not an
   exact computation. The effective exact-fidelity threshold for this
   dataset was 6 qubits (see the wave-4 notes in
   `data/v6/e21/metadata.json`).
8. **Missing provenance for pre-provenance-era runs.** `git_commit` is
   null in the metadata of E22, E23, E24 and SOTA (not recorded at
   generation time); several seeds in E23/E24/E25/SOTA were defaulted to
   42 because the originals were not recorded.
9. **E20 `compiler_status` carries error strings.** Some cirq rows hold
   parse errors (`'sx' is not defined in this scope`) instead of `ok`;
   their count columns are NaN and must be excluded before aggregation.
10. **SOTA aggregate reduction columns are percentages.** Unlike the
    fractional `reduction` convention, all `*_reduction` columns in
    `sota_comparison_aggregated.csv` are in percentage points.

## Data Types and Constraints

### Integer Columns
- `run_id`: `>= 0`
- `n_qubits`: `>= 1` (physically meaningful: `>= 2`)
- `depth`: `>= 1`
- `seed`: `>= 0`
- `trial`: `>= 0`
- `original_size` / `baseline_gate_count` / `gate_count_total`: `>= 1`
- `optimized_size` / `optimized_gate_count`: `>= 0` (can be 0 if all gates cancel)
- `optimized_depth`: `>= 0`
- `optimized_2q_gates`: `>= 0`
- `optimized_cnot_count`: `>= 0`
- `baseline_t_count`: `>= 0`
- `optimized_t_count`: `>= 0`
- `n_edges`: `>= 0`

### Float Columns
- `reduction`: `0.0 <= reduction <= 1.0`
- `reduction_pct`: `0.0 <= reduction_pct <= 100.0`
- `fidelity`: `0.0 <= fidelity <= 1.0`
- `runtime_seconds`: `>= 0.0`
- `depth_reduction`: `0.0 <= depth_reduction <= 1.0`
- `two_qubit_reduction`: `0.0 <= two_qubit_reduction <= 1.0`
- `cnot_reduction`: `0.0 <= cnot_reduction <= 1.0`
- `t_count_reduction`: `0.0 <= t_count_reduction <= 1.0`
- `theoretical_max`: `0.0 <= theoretical_max <= 1.0`
- `ceiling_gap`: `>= 0.0`
- `structural_upper_bound_reduction`: `0.0 <= value <= 1.0`
- `observed_best_reduction`: `0.0 <= value <= 1.0`

### Boolean Columns
- `success`: Do not pool across schema generations. Frozen v2_fixed--v8 optimizer rows generally used a 0.20 reduction threshold; future code uses 0.05 plus the configured fidelity threshold. Legacy compiler rows may be fidelity-only. Recompute from `reduction` and `fidelity` for comparative analysis.

## Missing Value Policy

| Scenario | Handling |
|----------|----------|
| Failed optimization | `optimized_size = original_size`, `reduction = 0.0`, `fidelity = NaN` |
| Timeout | `optimized_size = original_size`, `reduction = 0.0`, `fidelity = NaN`, `runtime_seconds = timeout_value` |
| Fidelity > 1.0 (numerical noise) | Clamped to `1.0` |
| Fidelity < 0.0 (numerical noise) | Clamped to `0.0` |

## Provenance and Versioning

All data files include provenance columns (appended by `src/provenance.py`):
`git_commit`, `source_hash`, `input_circuit_sha256`, `output_circuit_sha256`,
`python_version`, `qiskit_version`, `numpy_version`, etc.

Data versions:
- **v2_fixed**: E1–E5 (Greedy bug fixed)
- **v3_extended** (superseded → v5): E10
- **v4**: E11–E13 (real circuits, compiler baselines, structural ceilings)

per experiment.
